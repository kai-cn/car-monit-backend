## 依赖兼容性问题与处置（据实记录）

在 3.15.2 下按原 pin 安装失败，逐项升级：

| 包 | 原 pin | 新 pin | 原因 |
|---|---|---|---|
| `orjson` | 3.10.13 | 3.13.0 | 旧版 PyO3 0.23 不支持 3.15，源码构建报 `newer than PyO3's maximum supported version (3.13)` |
| `Pillow` | 11.1.0 | 13.0.0 | 旧版无 cp315 wheel，源码编译缺 jpeg 头；新版提供 cp315 wheel |
| `pydantic` | 2.10.4 | 2.14.4 | 其 `pydantic-core` 2.27.2 用 PyO3 0.22，不支持 3.15 |
| `pydantic-settings` | 2.7.0 | 2.16.3 | 跟随 pydantic 升级 |
| `requires-python` | `>=3.12` | `>=3.15.2` | 与项目目标一致 |

其余锁定依赖（`fastapi 0.115.6` / `starlette 0.41.3` / `uvicorn 0.34.0` / `SQLAlchemy 2.0.36` 等）无需改动。

## GitHub 拉取/推送问题修复（同日补记）

- 根因：WSL 的 DNS 服务器 `172.29.16.1` 把 `github.com` / `api.github.com` 污染为 `127.0.0.1`；
  HTTPS git 与 `wsl-git`（Windows git.exe）均 connection reset。
- 修复：在 `/etc/hosts` 固化 `140.82.112.3` 对应 `github.com`、`api.github.com`、
  `codeload.github.com`、`www.github.com`；备份写在 `/etc/hosts.bak-git-fix-*`。
- 注意：`140.82.112.6` 只服务 API（git smart HTTP 超时），不能用于 git；`140.82.112.3` 同时支持 git/api/codeload。
- 认证：Windows 版 helper 的缓存路径 `D:\work\...` 在 WSL 无效；新增
  `runtime-logs/git-credential-ghcached-wsl.py`，复用 `gh_cred.py` 的 token，
  并注册到 `credential.https://github.com.helper`（先空值清 GCM，再注册本地 helper）。
- 验证：`git fetch origin master` 成功（`1c3634b0..a2ffe6d7`），`git reset --hard origin/master` 后本地工作树干净；
  `git push origin master` 成功（`a2ffe6d7..422c781e`），`git ls-remote` 远端 HEAD 一致；
  `curl` 的 `git-smart` 探测返回 200。
- 修复脚本：`runtime-logs/fix-github-connectivity-wsl.sh`（幂等，先备份 hosts 再固化 IP 与 helper）。
- 待确认：WSL 重启后 `/etc/hosts` 是否被自动生成覆盖；若覆盖需把条目写入 Windows 侧
  `C:\Windows\System32\drivers\etc\hosts`，或把 `/etc/wsl.conf` 的 `network.generateHosts` 设为 false。
