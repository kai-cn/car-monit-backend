# 2026-11-24 基准口径纠错

## 用户纠正

用户审阅后指出：为了让 `body.code=200` 而把本应抛出的业务错误改成成功响应，是完全错误的理解。必须恢复 Java 基准及对应多语言实现中的真实业务错误语义。

## 新口径

- 不再以“所有端点 `body.code=200`”为目标。
- 读取类接口（列表、分页、按主键查询）必须先从本地数据库真实表中取得一个存在的主键，更新端点基准后再比较。
- 所有读取类接口以 Java 基准为准：JSON 结构一致、键顺序可不同；更换后端实现后前端应无感。
- 本应报错的业务场景（任务不存在、缺必填参数、非法资源、缺数据等）应恢复错误响应，并由各语言保持一致的结构与 code。

## 保留项

保留表名大小写、列名、数据源/端口、JSON 序列化、编译依赖、日志目录等真实基础设施修复；只回滚错误口径降级。
