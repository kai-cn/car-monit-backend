## 完整环境版验收：两处 CI 故障根因与修复（2026-11-25 晚）
按用户要求重构的完整复刻 WSL 版（ES + 9902 下游 + 四语言强制全跑）推送后触发验收，暴露两个确定性故障：

### 故障 1：backend run `45636059407` baseline 采集僵死（in_progress 卡 30+ 分钟）
- 现象：baseline job 停在「Start 9902 downstream + baseline, collect contract」，run `updated_at` 从 14:37:20 起不再变化，手动 cancel 返回 202。
- 根因：`generate_junit_suite.py:99,284` 的 `HttpURLConnection.setReadTimeout` 默认读 env `HTTP_TIMEOUT_MS=60000`（60s）。完整环境版让端点真正访问 9902/ES，桩数据服务未就绪的端点逐个挂起等 60s，190 端点累积数十分钟；workflow 未显式注入 `HTTP_TIMEOUT_MS`，故走默认值。
- 修复：baseline + candidates 两个采集步骤均显式注入 `HTTP_TIMEOUT_MS: '12000'`（12s，WSL 正常端点远快于此），挂起端点由 60s→12s，全量端点可在单 job 内完成。

### 故障 2：api run `45638800711` baseline failure（exit 1，契约未生成）
- 现象：`Build Java baseline + 9902 downstream + JUnit` 步骤中 `curl: (22) The requested URL returned error: 429` 连续 16 次，junit.jar 下载失败 → `test -s` 失败 → exit 1；artifact 里无 junit-contract.json。
- 根因：junit-platform-console-standalone-1.10.2.jar 仅从 Maven Central 单一下载，两个仓库并行 + 本轮多次 CI 使 GitHub 共享出口 IP 被限流（429）。
- 修复：改为 4 镜像源顺序回退（repo.maven.apache.org → repo1.maven.org → 阿里云 central → 华为云 maven），任一成功即 break，全部失败才 error。

### 修复推送与复验（第一批）
- 修复 commit：backend `3202a9da11e6` / api `9e031b103e32`（message：junit.jar 多镜像回退规避429 + 采集超时12s避免挂起端点卡死）。
- 复验 run：backend `45643438682` / api `45643449433`（15:17 触发）。
- 结果：
  - **api baseline 转为 success**（15:21:37→15:24:48，采集 52 端点仅 3m11s），证明多镜像修复 429 生效。

  - backend baseline 仍卡第 10 步（15:22 起 20+ 分钟、updated_at 停滞）——190 端点 + 部分 9902 下游端点挂起，12s 超时未完全兜住，最终 cancel。

### 故障 3：api 候选比较阶段 failure（第 18 步）

### 故障 4（核心）：Java baseline 契约全 status=0 —— 假基准导致对齐率 0/N
- 现象：api 四语言 artifact `structure-summary.md` 显示**总数 52 / 通过 0 / 差异 52**（本地 WSL 口径应为 47/52）。明细 `base_st=0`（Java 基准 status 全 0），而候选 `status=200/500` 为真实响应。
- 定位：api baseline job 日志显示 9902 下游 READY，但 `junit-auth-token.py` 在启动 3 分钟后仍 `ConnectionRefusedError [Errno 111]` 连不上 19903 —— Java baseline app.jar 根本没起来。Gate 只看 `endpoint_count>=10` 且无熔断 body，误判 success（契约全 0 蒙混过关）。
- 根因（对照本地 `run-read-only-matrix.sh`）：
  1. workflow baseline app.jar 用 `JAVA_HOME_25` 启动，但被测 app 是 Spring Boot 2.x（JDK25 下 ASM/CGLIB 不兼容，启动失败）；本地用系统默认 java（JDK8）；
  2. 数据源参数按 app 不同：backend ruoyi-admin 用 MySQL druid，api pro-business-api 用 PostgreSQL dynamic；workflow 对所有 app 统一传 MySQL druid，api 侧数据源初始化失败；
  3. 缺 `token.secret` / `spring.elasticsearch.uris` / `vehicle-monitor.base-url`（本地都有）。
- 修复：baseline app.jar 启动按 `app` 分支（api=JDK8+PG dynamic，backend=JDK8+MySQL druid），补齐上述参数；加 19903 未监听快速止损（tail app.log + exit 1）；Gate 增加 status=0 比例 >50% 拦截，杜绝全 0 假契约。
